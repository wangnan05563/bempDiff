# BempDiff Tauri 桌面壳 · 本机实测 Checklist

> 用途：在**本机 Windows**（沙箱无 Rust/WebView2/显示环境，无法冒烟）逐项验证 P4 桌面壳。
> 关键事实：`cargo tauri build`（release）才会自动拉起随包 JRE、端口探活、内嵌窗口；
> `tauri dev`（debug）**只验 Web UI**，不启动 JRE —— 真正验收必须走 release 安装包。

---

## 0. 前置环境（一次性）
- [ ] Windows 10/11 64-bit
- [ ] Rust 工具链（rustup，stable）：`rustc --version` / `cargo --version`
- [ ] Tauri 2 前置：Visual Studio Build Tools（**C++ 桌面开发 / MSVC**）+ WebView2 运行时（Win11 自带；Win10 装 Evergreen）
- [ ] Node 22 + npm：`node -v`
- [ ] JDK21（**含 jmods**，用于 jlink 瘦 JRE）—— 项目自带 `prototype/toolchain/zulu21.52.15-ca-jdk21.0.12-win_x64/`；或本机 JDK21
- [ ] 网络可用（首次 `npm install` 需拉 `@tauri-apps/cli`、vue、vite）

## 1. 取代码与依赖
- [ ] `cd prototype && npm install`（装 `@tauri-apps/cli`）
- [ ] `cd webui && npm install`（装 vue / vite / bootstrap 等，见 webui/package.json）
- [ ] （可选，建议）本机 `cd webui && npm run build` 重建 `webui/dist`（沙箱曾锁 dist，本机正常）

## 2. 一键打包（生产安装包）
- [ ] 跑 `powershell -File scripts/build_tauri_app.ps1`
  - 自动完成：编译 `java_core` → `dist_input/app/bempdiff.jar`、复制 `cfr.jar`、
    `jlink` 瘦 JRE → `dist_input/jre`、`vite build` → `dist_input/webui`、
    `cargo tauri icon`、`cargo tauri build`（NSIS）
- [ ] 期望产物：`src-tauri/target/release/bundle/nsis/BempDiff_0.1.0_x64-setup.exe`
- [ ] 失败排查：
  - `npm install` 网络/缓存错 → 确认能联网；`npm cache clean --force` 后重试
  - `jlink` 报找不到模块 → 确认 JDK21 含 `jmods/`（toolchain 目录完好，未被掏空）
  - `cargo tauri build` 报 MSVC / WebView2 缺失 → 装 VS Build Tools + WebView2
  - 图标缺失 → `npx tauri icon <png>` 重新生成 `src-tauri/icons/`

## 3. 安装与启动
- [ ] 双击 `BempDiff_0.1.0_x64-setup.exe` 安装
- [ ] 开始菜单 / 桌面捷径 → 双击 `BempDiff`
- [ ] **预期**：约 1–3s 内弹出窗口「BempDiff — 票据系统 WAR/JAR 差异比对与智能分析」，
      内嵌 Web UI 加载完成（**无需手动起服务、无需装 Java**）
- [ ] 失败排查：
  - 窗口空白 / 打不开 → 检查安装目录 `BempDiff/resources/` 下是否齐 `jre/`、`app/bempdiff.jar`、
    `app/cfr.jar`、`webui/`；看 `cargo tauri build` 日志里 `launch_and_serve` 的报错
  - 卡在启动 >30s → 后端 30s 内未就绪（JRE 路径错 / 端口占用）；
    确认 `resources/jre/bin/java.exe` 存在

## 4. 功能验收（逐项勾选）
| # | 验收项 | 操作 | 预期 |
|---|---|---|---|
| F1 | 原生文件对话框（免上传） | 选「老包」→ 弹**系统文件框**选 `.war`/`.jar` | 路径直接填入，无上传进度、不离开本机 |
| F2 | 原生文件夹对话框 | 切到文件夹模式选目录 | 系统文件夹框，返回绝对路径 |
| F3 | 比对流程 | 选两包 → 开始比对 | 差异树出现、统计正确（样本 war：added1/deleted1/modified5/unchanged1）|
| F4 | 双栏源码 diff | 点类节点 | 中栏双栏 diff，长行不截断（可切「换行/不换行」）|
| F5 | 报告生成 | ⚙设置（填 AI 或关闭）→ 查看/导出报告 | 「报告预览」弹窗，章节齐全；破坏性清单 / 审计摘要正确 |
| F6 | 导出资产 | 导出报告 `.md` / 差异资产 zip | 文件落到本机选定目录 |
| F7 | **AI 连接测试（TLS）** | ⚙设置填 provider（BaseURL/Key）→ 连接测试 | 返回成功（证明 jlinked JRE 含 `jdk.crypto.ec`，HTTPS 调 AI 通）|
| F8 | AI 分析 | 开启 AI → AI 分析 | 右侧四 Tab 出概览/逐文件/影响/测试要点；无 Key 走 Mock 兜底 |
| F9 | 退出回收 | 关窗口 / 退出 | 任务管理器确认**无残留 `java.exe`** |

## 5. 仅 UI 开发联调（不验证生产壳）
- [ ] `powershell -File scripts/build_tauri_app.ps1 -AssembleOnly`（只 assemble `dist_input`，不打安装包）
- [ ] 另开终端手动起后端（端口 18765，与 vite 代理一致）：
  ```bat
  dist_input\jre\bin\java.exe -cp "dist_input\app\bempdiff.jar;dist_input\app\cfr.jar" ^
    com.bempdiff.Main server --webroot dist_input\webui --port 18765
  ```
- [ ] `cd webui && npm run dev`（`tauri dev` 等价）→ 打开 vite@5173 开发页
- ⚠️ 注意：`tauri dev` 是 **debug 模式，不会自动拉 JRE**，必须上面手动起后端；
  它只验 Web UI 与 `/api` 代理，**不验证** JRE sidecar / 端口探活 / 内嵌窗口（那是 release 的职责）。

## 6. 已知风险与回滚
- ⚠️ 窗口空白多为 `resources` 缺项（jre / app / webui 任一项没打进安装包）→ 重跑 build 脚本，确认 assemble 阶段无报错。
- ⚠️ AI 连接测试失败先查 BaseURL / Key / 代理；若报 TLS / 算法类异常，说明 jlink 漏了 `jdk.crypto.ec`（脚本已显式加，正常不会）。
- ⚠️ 退出后仍有 `java.exe` → 检查 `src-tauri/src/lib.rs` 的 `ExitRequested` 杀进程逻辑；任务管理器手动结束。
- 回滚兜底：旧 JavaFX 安装包（若本机仍保留 `dist_exe/BempDiff/BempDiff.exe`）暂可作对比；或任何时候都能用 headless 子命令
  `BempDiff.exe compare/report/export ...` 直接出结果。

## 7. 验收通过标准
- [ ] 安装包生成且可安装
- [ ] 双击启动即出 Web UI（无需装 Java / 手动起服务）
- [ ] **F1–F9 全部通过**（尤其 F1 原生对话框、F7 TLS 调 AI）
- [ ] 退出无 `java` 孤儿进程

## 8. 静态预检结论（沙箱内已完成，本机可跳过）
> 本地实测前已在沙箱做**代码级静态预检**（无 Rust/WebView2 不冒烟），覆盖 assemble 阶段 + `tauri dev`(debug) 路径 + 配置完整性。
> 结论：**产物与配置链路均健康**，唯一需本机实跑的是 `cargo tauri build` / `tauri dev` 与 F1–F9。

### 8.1 assemble 阶段（§2 前置）✅
- `bempdiff.jar`：180KB、91 个 `com/bempdiff` 类、`Main-Class=com.bempdiff.Main` ✅
- `cfr.jar` 复制 ✅
- jlink 瘦 JRE：`java.base,java.logging,jdk.httpserver,jdk.crypto.ec,jdk.crypto.mscapi,jdk.jdeps` → 48MB，`jre/bin/java.exe` 存在 ✅
- `vite build` → 27 模块 109KB JS，镜像 `dist_input/webui` ✅
- 端到端冒烟（assemble 产物起 `server --port 18821`）：TCP 1s 就绪、`GET /` 返回 index.html、`GET /api/config` 200、TLS 模块随瘦 JRE 加载无误 ✅
- 留意：`dist_input/classes` 为 `javac` 中间产物（未进 resources 映射），**不打包、无害**，可留可删。

### 8.2 `tauri dev`（debug）路径 ✅
- `lib.rs` `#[cfg(debug_assertions)]` **不拉 JRE**（正确：dev 走浏览器工作流，避免与开发态冲突）✅
- `tauri.conf.json` `devUrl=http://localhost:5173` + `beforeDevCommand=npm run dev` ✅
- `vite.config.js` 代理 `/api → 127.0.0.1:18765`；`Main` `server` 默认端口 = `18765`（一致）✅
- `server` 子命令 `--webroot` **可选**（null 时 `BempServer.handleStatic` 回落占位首页，SPA 由 vite 提供）✅
- `client.js` `BASE=''` 同源（dev 经代理 / 生产经 sidecar 同源）✅
- cfr 解析：`server` 路径不传 `--cfr` → `cfrJar=null` → `Decompiler` 走**进程内 CFR**（cfr.jar 已在 `-cp`），反编译可用 ✅
- `BempServer` 全响应加 `Access-Control-Allow-Origin:*`，跨端口（5173→18765）也通 ✅

### 8.3 配置完整性 ✅
- `frontendDist=../webui/.tauri-placeholder` → `index.html` 存在（352B），Tauri 校验通过 ✅
- `resources` 映射 `app/jre/webui` 精确对应 `dist_input`（assemble 已生成）✅
- `bundle.icon` 引用 `icons/*`（当前缺失是**预期**：build 脚本 `cargo tauri icon` 从 `prototype/bempdiff-logo.png` 自动生成；该源 PNG 存在）✅
- `targets=["nsis"]`、`withGlobalTauri=true`、`security.csp=null` ✅

### 8.4 非阻塞残留（留意即可）
- `scripts/gen_bemp_icon.py` 已修正：`PNG_PATH` 改为 `prototype/bempdiff-logo.png`（即 build 脚本的 `$Logo`），母版升到 **1024×1024**；重跑即可产出高清图标源，`cargo tauri icon` 据它生成锐利安装包图标。`assets/bempdiff.ico` 为遗留（旧 jpackage，已退役），无害。
- `dist_exe/BempDiff/BempDiff.exe` 为旧 JavaFX 残留，被 Defender/系统锁，沙箱删不掉；**无害**，本机资源管理器手动删或重启清理。
