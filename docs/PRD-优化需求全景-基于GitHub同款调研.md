## 1. 背景与问题陈述

BempDiff 是桌面端 war/jar/zip/文件夹差异化对比 + AI 分析工具（Electron + Vue3 + Java 21 sidecar）。当前一期/二期交付了核心对比链路（分层 L0/L1/L2、CFR 反编译、两阶段 AI、构建元数据噪声归一化、i18n 全量化）与 arm64 三平台打包链路。

对标 GitHub 同类产品后发现三个差距带：
1. **交互精细度**：头部 diff 工具（difftastic ★26k / delta ★32k / monaco ★47k）已把「字符级行内高亮、折叠未变更区、语法感知」做成标配，BempDiff 的行级对比在大文件场景导航效率吃亏；
2. **场景纵深**：japicmp（★781）验证了「jar 版本对比 + API 兼容性分级」的刚需，但没有任何产品把「归档对比 + 反编译 + 兼容性语义 + AI 分析」垂直整合——这是 BempDiff 的空位；
3. **基础体验**：亮/暗主题（BC 5 才补齐，市场确认标配）、CLI/CI 模式（桌面工具进入流水线的明确趋势）、会话管理等。

## 2. 产品定位与目标用户

- **定位**：面向 Java 后端交付/升级场景的「包级差异化对比 + 变更智能分析」工具，差异化主线 = **Java 归档 + 反编译 + 语义分层 + AI** 垂直整合。
- **目标用户**：交付工程师（升级包验收）、QA（变更影响评估）、研发（版本间回溯）。

## 3. 产品目标与成功指标

| 目标 | 指标 | 基线（2026-10） |
|---|---|---|
| 大文件导航效率 | 12000 行夹具「跳下一处差异」操作时长 | 已达标（12/12），折叠未变更区后目标再降 50% |
| 对比噪声 | 格式化/重排类假差异占报告比例 | 无 AST 对齐，100% 行级呈现 |
| 桌面体验 | 暗色模式支持、更新链路零缺陷 | T01726 降级缺陷已修复；暗色未支持 |
| 流水线渗透 | CLI/CI 调用占比 | 0（无 CLI 入口） |

## 4. 需求详述

> 优先级定义：P0=缺陷修复/市场标配补齐（当前里程碑）；P1=竞争力建设（下个里程碑）；P2=远期演进（规划池）。

### P0（缺陷修复与标配补齐）

#### FR-001 更新按钮降级防护 ✅ 已完成（T01726，提交 cca779d）
- **用户故事**：作为已最新版本的用户，我不想看到「立即更新」按钮，以免误把旧版安装回本机。
- **实现**：About.vue 按钮显隐增加 `result.upToDate === false` 判断；`upToDate=null`（版本未知）同样不显示。
- **验收**：真机 CDP 双分支 4/4 PASS；单测护栏 3 条（全量 366/366）。

#### FR-002 字符级行内高亮（word-diff）
- **用户故事**：作为研发，同一条变更行内我想直接看到改了哪几个字符，而不是整行标色后逐字肉眼比对。
- **需求**：diff 视图对「修改型变更行」做字符级分段高亮（新增段绿/删除段红，复用现有差异配色语义）。
- **实现参考**：diff2html/react-diff-view 的 word-diff 算法；java-diff-utils 提供 inline-level diff。
- **验收标准**：① 单行内多处修改均正确分段；② 超长行（>2000 字符）性能可接受（<50ms/行）；③ 中英文/代码混排无错位；④ i18n 双语环境渲染一致。
- **涉及模块**：webui DiffView 渲染层。

#### FR-003 折叠未变更区（collapse unchanged）
- **用户故事**：作为交付工程师，对比 5000 行只改了 20 行的文件，我希望默认只看到差异周边上下文。
- **需求**：未变更区默认折叠为「⋯ 展开 N 行」，可整块展开/全部展开；折叠状态不干扰「下一处差异」跳转（T00876 链路）。
- **实现参考**：monaco diff editor gutter 折叠条；diff2html 折叠交互。
- **验收标准**：① 默认上下文 3~5 行可配置；② 折叠/展开不触发布局抖动（无滚动位置跳变）；③ 大文件（12000 行）折叠态滚动帧率不劣化；④ 键盘跳转自动展开目标块。
- **涉及模块**：webui DiffView。

#### FR-004 亮/暗/跟随系统三态主题
- **用户故事**：作为夜间使用的用户，我希望界面跟随系统暗色，减少视觉疲劳。
- **需求**：设置项三选一（亮/暗/跟随系统）；差异配色提供双套语义色板；Bootstrap 5.3 data-bs-theme 切换 + CSS 变量全量梳理。
- **实现参考**：BC 5 系统级暗色（2026 年市场确认标配）；shiki 主题体系供后续扩展。
- **验收标准**：① 全部 22 个组件面 + 帮助正文在双主题下可读（WCAG AA 对比度）；② 暗色下差异高亮/树置灰/AI 结论区配色语义不变；③ 跟随系统实时切换无刷新；④ 主题偏好持久化。
- **涉及模块**：webui 全局样式 + 设置中心。

### P1（竞争力建设）

#### FR-005 CLI/CI 模式
- **用户故事**：作为流水线维护者，我希望在 CI 中直接调用对比并产出报告，作为升级包验收门禁。
- **需求**：`bempdiff-cli --left <A> --right <B> --report out.html [--json out.json] [--fail-on-diff]`；复用 Java sidecar 对比内核，无 GUI 依赖；支持 `--apikey ""` Mock 模式跑 AI。
- **验收标准**：① 无显示环境（headless）可运行；② HTML/JSON 报告与桌面端结论一致；③ exit code 语义明确（0 无差异 / 1 有差异 / 2 错误）；④ 单包对比 <30s（≤200MB 基线）。
- **依赖**：Java sidecar 现有 Server 接口 + 新 CLI 入口。

#### FR-006 语法感知 diff（AST 对齐）
- **用户故事**：作为研发，格式化调整/方法重排/import 变动不应该被报告成实质变更。
- **需求**：L2 层反编译源码对比引入 tree-sitter Java AST 对齐（可降级行级），变更分类标注：实质逻辑变更 / 格式或位置变更。
- **实现参考**：difftastic（★26k）结构化 diff；tree-sitter-java grammar 现成。
- **验收标准**：① 重排 + 格式化夹具零假差异；② 实质变更不漏报；③ 对比耗时增量 ≤30%；④ 不可解析文件自动降级行级并提示。
- **关联**：与 FR-012 API 兼容性分级共享 AST 基建。

#### FR-007 API 兼容性语义分级
- **用户故事**：作为升级验收方，我需要一眼知道这次 jar 升级有没有二进制不兼容风险。
- **需求**：基于反编译类信息输出变更分级：新增 API / 移除 API / 签名变更 / 行为变更（AI 辅助）；不兼容项醒目标注并可导出。
- **实现参考**：japicmp（★781）语义模型 + 分级配色。
- **验收标准**：① 演示夹具四类变更识别准确率 100%；② 结论进入 AI 分析上下文；③ 报告含兼容性摘要段。
- **差异化**：japicmp 无反编译/AI，BempDiff 可给出「行为级」结论。

#### FR-008 用户可配置忽略规则集
- **需求**：忽略规则（正则/路径/键模式）用户可视化管理，支持导入导出；现有构建元数据噪声归一化升级为规则体系的一个内置预设。
- **验收标准**：① 规则即时生效于树与文件视图；② 预设规则集可一键恢复；③ 规则文件 JSON 格式可版本化。
- **涉及**：DiffEngine 过滤管线 + 设置中心。

#### FR-009 对比报告导出（HTML/Markdown/JSON）
- **需求**：一键导出含树摘要、差异明细、（可选）AI 结论的独立报告文件，供评审归档。
- **验收标准**：① 三格式内容一致；② 报告离线可打开（无外部依赖）；③ 大报告（500 文件）导出 <10s。

#### FR-010 对比会话管理
- **需求**：最近对比历史（左右输入+模式+时间）、命名保存常用对比任务、一键重放。
- **实现参考**：BC Session 概念。
- **验收标准**：① 历史持久化（本地加密敏感字段——沿用 Key 不落盘原则）；② 重放参数完整还原。

#### FR-011 一键导出脱敏诊断包
- **需求**：出错时导出脱敏日志+环境信息 zip，替代口头描述环境。
- **验收标准**：① 包内不含 API Key/用户路径敏感段（自动脱敏白名单机制）；② 体积 <5MB。

#### FR-012 AI 变更影响分析
- **用户故事**：作为 QA，我希望 AI 不只「描述改了什么」，还回答「影响哪些调用方、风险多高」。
- **需求**：基于反编译 AST + 调用关系，对实质变更输出影响面（受影响类/方法清单）+ 风险等级，进 AI 第二阶段提示词。
- **实现参考**：pr-agent（★13k）影响分析思路。
- **验收标准**：① 影响面与人工判断一致率抽样 ≥80%；② 成本闸门与脱敏规则全程生效；③ 结果可解释（列出证据链）。

#### FR-013 AI 成本透明化
- **需求**：分析前显示预估 token/费用（沿用成本闸门阈值），分析后显示实际消耗明细。
- **验收标准**：① 预估误差 <30%；② 超阈值阻断行为与现状一致；③ 明细含输入/输出分段。

#### FR-014 语法高亮主题包
- **需求**：代码区语法高亮主题可选（内置 github-dark / one-dark 等），基于 CSS 变量或轻量高亮库实现。
- **验收标准**：① 与 FR-004 双主题联动；② 至少 4 套内置主题；③ 切换即时生效。

#### FR-015 目录树筛选与 gutter 快捷操作
- **需求**：树筛选（只看差异/类型/正则）、列排序、状态图例；diff 行 gutter 增加「复制到对侧」「标记已审阅」与 j/k/n/p 键位。
- **验收标准**：① 筛选与树置灰口径一致；② 标记已审阅持久化到会话（FR-010）；③ 键位不与现有快捷键冲突。

## 5. 非功能需求（全局约束，各 FR 均须满足）

1. **i18n 铁律**：新增文案必须 en-US 非空译文（`allKeys()` 护栏）；禁用 `t` 作数据变量名；纯数据表用 `xxxKey + xxx` 双字段。
2. **性能 SLA**：≤200MB 包对比 <30s、big500（92113 条目/515MB）p50≤8s——任何渲染增强不得劣化该基线。
3. **安全**：API Key 默认不落盘；AI 链路脱敏 + 成本闸门；`--apikey ""` 强制 Mock。
4. **输入模式铁律**：不做「入口合并/类型自动识别」类改造（用户裁决）。
5. **兼容**：Windows x64/arm64、Linux arm64、macOS arm64（NSIS 两层解包核验流程沿用）。

## 7. 风险与开放问题

1. **AST 对齐性能**（FR-006）：tree-sitter 增量解析在超大反编译文件上的耗时需早验证——建议 M2 首周做 spike。
2. **AI 一致率**（FR-012）：影响分析依赖调用图质量；反编译源码的调用图精度是上限，需抽样校准。
3. **CI ARM runner 排队**：免费 runner 长排队（实测 17h+）影响交付节奏，M2 前评估自建 runner 或付费额度。
4. **主题改造面**（FR-004）：Bootstrap 组件 + 自定义 CSS 变量双体系，改造面大，建议先做全量色值审计再动手。
5. **开放问题**：报告导出（FR-009）是否纳入 AI 结论由用户勾选（涉脱敏边界）——待评审定。
