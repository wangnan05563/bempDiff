# 文件夹 / WAR / ZIP 包对比优化：异步多线程逐层解包 + AI 解包完成后执行 实施计划

> **For agentic workers：** REQUIRED SUB-SKILL：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐步实施本计划。步骤用 `- [ ]` 复选框跟踪。

**Goal（目标）：** 在现有内存惰性展开基础上，新增"物理平铺解包"引擎：自动识别 文件夹 / WAR / ZIP，多线程异步逐层解包至原子文件，产出含全部嵌套文件的平面快照，差异统计与 AI 候选覆盖递归子文件；利用既有 `job.complete()` 作为等待屏障，保证 AI 分析仅在解包完全完成后执行；落盘解包状态报告（JSON）与错误日志（文本）。

**Architecture（架构）：** 沿用现有 `runCompareTask -> parse -> diff -> stats -> job.complete()` 单虚拟线程管线。新增 `NestedUnpacker`（有界平台线程池 + `invokeAll` 超时），在 `parse` 阶段把快照内所有 `FileClass.ARCHIVE` 条目（嵌套 zip/jar/war/tar 等）递归物理解压到临时目录并改由磁盘定位，把内部原子文件按 `外层键/内层路径` 平面化追加进 `entries`；Diff/AI 天然消费平面快照。等待屏障复用 `job.complete()`（仅 DONE 后才允许 AI），解包异常走逐文件隔离 + 超时部分完成，「解包状态报告 + 错误日志」落盘并从 `Job` 透出。

**Tech Stack（技术栈）：** Java（JDK 平台线程池 `Executors.newFixedThreadPool` + `invokeAll`，虚拟线程外层调用方）、java.util.zip、内置临时目录、复用 `Json` 类手写 JSON。前端 Vue3 + Bootstrap（`DiffTree.vue` 已按 `/` 分段分组平面 key，验证即可）。

---

## 设计决策（先约定，避免实施时反复）

1. **不改 UI 差异树模型**：平面展开后的 key 为 `WEB-INF/lib/<jar>/<inner>` 形态，前端 `DiffTree.vue`/`dir_tree.js` 已按 `/` 分段分组，统计 `counts = computed(() => 遍历 tree)` 自动覆盖递归子文件，故 `M-C` 仅需验证，不重构渲染。
2. **屏障 = 既有 `job.complete()`**：解包必须在 `runCompareTask` 内同步等待完成（`invokeAll().get()` 带超时）之后才 `complete()`；`handleReport`/`handleAiAnalyze` 已要求 `DONE`，即构成"AI 待解包完成后"的硬约束，无需新信号量。
3. **入口最小侵入**：类型识别与 WAR 语义复用 `PackageParser.detectType/classify`；不加新对比路由，解包报告经 `/api/job/{id}/unpack-report` 读取 + 落盘文件，错误日志经 `resources/bempdiff/logs/unpack-<jobId>.log`。
4. **配置驱动**：线程池大小/超时/最大深度全部外置于 `CompareOptions`（`leftType` JSON 透传，默认线程池 4、超时按任务量自适应），不写死。

**待确认边界（实施前用 AskUserQuestion 收口）：**
- 物理平铺是否仅对「最内层为可读内容的聚合包」开启，还是对任意 `ARCHIVE` 类型一律展开？（默认：对 `.war/.zip/.jar/.ear` 内的嵌套归档递归展开；`.tar/.tgz` 因读取两遍开销大，默认仅一层，可配置 `maxDepth` 放宽。）

### Task 2：`NestedUnpacker` 多线程递归物理展开 + 屏障

**Files:**
- Create: `com/bempdiff/unpack/NestedUnpacker.java`
- Modify: `com/bempdiff/parse/PackageParser.java`（`parse` 尾部插入 flatten 阶段）
- Modify: `com/bempdiff/server/CompareOptions.java`（新增 unpack 配置）

- [ ] **Step 1：失败测试**——构造 `a.zip` 内含 `b.jar` 内含 `com/hundsun/X.class`，断言 flatten 后 `entries` 含 `a.zip/b.jar/com/hundsun/X.class` 且 `fileClass=CLASS`

```java
public static void testNestedFlatten(TestContext t) throws Exception {
    Path zip = makeZipWithNestedJar();       // a.zip -> b.jar -> X.class
    PackageSnapshot snap = new PackageParser().parse(zip, cfg(false), false);
    NestedUnpacker u = new NestedUnpacker(new UnpackOptions(), tempDir());
    PackageSnapshot flat = u.flatten(snap, new UnpackReport("zip"));
    Asserts.truth(flat.getEntries().containsKey("a.zip/b.jar/com/hundsun/X.class"),
        "嵌套 jar 内 class 应平面展开");
}
```

- [ ] **Step 2：跑测试确认失败**（`flatten` 不存在）
- [ ] **Step 3：实现 `flatten`**——对有界池 `Executors.newFixedThreadPool(opts.threadPoolSize)`：
  1. 取 `snap` 中 `fileClass==ARCHIVE || fileClass==JAR`（且非磁盘目录）条目为根任务；
  2. 每任务：把外层条目流式落临时文件 -> 若仍为归档则以当前 key 为外层、内部条目递归展开并 `Future` 提交，逐层 `jarPath/innerPath` 拼 key；
  3. 原子文件（class/text/config 等）直接加入平面 `entries`，`EntrySource` 指向解包出的磁盘文件，`sha256` 用磁盘文件流式计算；目录条目跳过；zip-slip / 超限条目抛异常被 per-item 隔离捕获计入 `UnpackError`；
  4. `invokeAll(tasks)` -> `get(timeout)` 汇总；超时则回收未完成任务并标记 `report.incomplete=true`，返回已完成的平面快照。
- [ ] **Step 4：跑测试通过**
- [ ] **Step 5：在 `PackageParser.parse` 尾部调用**（`expandAll` 或检测到 `ARCHIVE` 条目时触发）：

```java
if (expandAll || containsArchive(entries)) {
    NestedUnpacker u = new NestedUnpacker(UnpackOptions.fromConfig(cfg), cfg.getTempRoot());
    return u.flatten(new PackageSnapshot(file, type, version, entries), report);
}
```

## 风险与护栏

- **zip bomb**：沿用 `HARD_CAP`（64MB/条目）双约束（声明+累计）；平面展开新增「临时目录总大小上限」防御。
- **超时保护**：`invokeAll.get(timeoutMs)` 超时回收未完成任务，`report.incomplete=true`，返回部分解包结果，AI 照常可产出但报告标注未完整解包项。
- **异常隔离**：per-item try/catch 计入 `UnpackError`，不中断整体任务。
- **并发安全**：`UnpackReport` 聚合用 `ConcurrentHashMap` + `synchronizedList`；临时目录每任务独立子目录避免命名冲突。
