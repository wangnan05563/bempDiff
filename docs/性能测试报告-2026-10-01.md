## 2. 总览

- **总请求 541,540，错误 0，真实缺陷 0**（全部原始样本实测，12 阶段全 200）
- 单发基线（预热后）：big200 parse **1.04s** / diff **1.07s**；decompile batch(topK=60) **33ms**（21 候选全成）；ai/report/export **12–23ms**

## 4. 结论与解读

1. **反编译吞吐线性扩展良好（外部并发）**：TPS 53 → 112 → 129 → 235（T1→T8，4.4×）；p50 仅从 15ms 升至 32ms。P0-1 进程内 CFR + P1-3 有界工作池的组合在 8 并发下未见拐点。
2. **内部线程缩放平坦属预期**：scale 档为单外部客户端顺序请求，单请求 15–21ms 被 parse 主导（2×719KB 夹具），进程内 CFR 对 21 个候选的反编译开销极小，内部线程数在外部观测上不可见。要测内部缩放需多外部并发（conc 档已覆盖）。
3. **重端点高并发为"设计内背压饱和"，非缺陷**：big200 解析 50 并发 p50 放大 ~50×、100 并发 ~105×（单发 1s → 52.8s/69.3s），与 Harness P0-2 注释「50 并发放大 49×、100 并发 90×」吻合；PARSE_GATE=min(核数,8) 有界排队使**错误率保持 0**，无雪崩、无 5xx、无超时缺陷。放大发生在排队维度，属容量型饱和（§2 #8 判据：单发正常 + 高并发劣化 = 资源饱和）。
4. **轻量端点余量充足**：ai/report/export 在 10 并发下 TPS 248（三端点合计），p99 ≤171ms。
5. **内存高水位**：5.4GB RSS 由 50–100 并发 × 411MB 夹具解析的峰值分配撑起并保持（JVM 默认 max heap 未设）；单用户桌面场景（默认 1 并发）不会进入该水位。若需压低，可为 sidecar 显式设 `-Xmx` 并调低 PARSE_GATE。

## 5. 限制声明

- **同机负载生成**：python 回放引擎与 SUT 同机，pdf50/100 高并发档尾延迟含负载机争抢成分（§2 #11）；以「单发基线 + 0 错误 + conc 档 p50 健康」旁证隔离真实服务延迟。
- **Mock AI**：ai 端点走 MockAiAnalyzer 离线回放，AI 延迟不反映真实上游。
- **big500 SLA 未复跑**（磁盘约束），沿用 2026-08-17 轮结论。
- JMeter 原生模式不可用（java.scripting 模块缺失），如需原生 HTML 报告需先补全 JDK（恢复 zulu21 或完整 JDK25）。
