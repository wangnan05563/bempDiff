## 修复 AI 分析「重新分析」重启竞态（aiControllers 归属守卫）
- **背景**：08-18 代码评审发现的「中」级潜在缺陷——`store.js` `runAiTaskStream` 的 SSE 回调（onThinking/onAnswer/onDone/onError）无归属守卫。「重新分析」时 `restartAiAnalysis` 先 `stopAiAnalysis`（abort 旧流 + `aiControllers.delete(id)`），再 `runAiTaskStream` 写入新 controller（同 key）；但旧流的异步回调（abort 后 onError/onDone 或残留 onAnswer）仍会触发 `aiControllers.delete(t.id)` 与 `t.answer += ...`，**删掉新 controller** + **污染新流答案/状态**。后果：① 新流丢失 abort 句柄，点「中断」无效；② 旧流残留字符追加进已重置的 `t.answer`。
- **修复**：四个回调统一加 controller 身份守卫——`if (aiControllers.get(t.id) !== controller) return`。仅当 map 中当前 controller 仍是本次创建的 controller 时才写入 task 状态/答案或 delete map。陈旧流回调整体忽略。
- **代码位置**：`bempdiff/webui/src/store.js` `runAiTaskStream`（L482-519）。
- **验证**：
  - `vite build` **36 模块通过**（3.28s，exit 0，index-Bi_zzCZU.js 160.88 kB）。
