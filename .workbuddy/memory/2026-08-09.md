## 性能压测续：decompile sweep 重启 + 亚线性缩放发现（晚间）

- **问题与决策**：旧后台 sweep（Oa8EOh）每个 decompile 计划 `duration=600s`，剩余 8 测试预计还需 ~76min，过慢。保留已完成的 scale T1/T2/T4（600s 充分采样），终止旧任务，将 scale/conc 时长收紧到 **180s** 重跑剩余 T8/T16/conc_T1..T8。
- **进程清理**：终止旧 harness（pid 39028）与游离 jmeter 进程（41764、3324）+ **16 个挂起 `java -jar cfr.jar` 孤儿**（疑似子进程 stdout 管道未排空导致 `waitFor()` 阻塞死锁）；以干净状态后台重启 harness（task **R9XlqJ**，含 JFR）。
- **文件锁坑**：孤儿 jmeter 占用 `jmeter/*.jmx` 句柄 → `gen_jmx.py` 写被锁（PermissionError）。绕过：新增定点补丁 `scripts/patch_jmx_duration.py` 生成 `*_r.jmx`（duration 600→180），避免触碰被锁原文件；后台 sweep（**KMzcZZ**）跑 `_r` 计划，结果写干净文件名。
- **关键发现（缩放曲线，已测 T1/T2/T4）**：decompile 内部线程扩展**严重亚线性** —— T1=113.2s(1.41s/class)、T2=82.6s(1.03s/class, 仅 1.37× 加速)、T4=87.5s(1.09s/class, 触顶且 p95=129s)。根因：每类起 JVM 冷启动 + 每子进程**重读大 jar** → 并发 I/O/CPU 争用。单纯加内部线程无效，必须进程内 CFR API / 长驻进程池（P0-1）。
- **报告草稿**：`性能测试报告-票据系统WAR-JAR差异比对与智能分析工具.md`，含已完成全部真实数据（parse 50/100 并发放大 49×/90×、ai/report/export @10 ~40s、diff big500 9.1s SLA 达标）、五维优化建议（P0-1 反编译进程池 / P0-2 解析并发上限 / P1 缓存·IO·背压）、瓶颈分析；decompile T8/T16/conc 6 点标记"测量中"。
- **KMzcZZ 完成 + 报告定稿**：6 个 decompile 数据点已全部测量并补入报告 4.4/4.5/§7。结论：① 内部线程缩放亚线性确认——T16 单请求 128.3s 相对 T1(113.2s) 仍无线性收益，T8 单样本 623s 属偶发异常（不纳入趋势）；② 外部并发墙实测——conc 1→8 单请求 **124.5s→478.8s（3.8× 退化）**，TPS 恒 ~0.01；③ CFR 子进程峰值 **43 个**（cfr_procs.csv 451 采样，avg=10）。报告已定稿（移除全部"测量中"标记，P0 瓶颈行并入 4.5 证据，§8.3 标记已完成）。harness 后台任务已退出（HARNESS_DOWN），清理孤儿 CFR 后环境干净，无基础设施进程受影响。

### 修复的真实代码缺陷（6 处）
1. `Decompiler.javap()` 误复用 `javaBin` 导致 `java -p -c` 报错 → 新增 `javapBin()` 推导 `javap.exe`（无 CFR 时降级全失败，P0）。
2. `MarkdownReport.writeToFile()` 跨盘父目录不存在抛 NoSuchFileException → 增加 `Files.createDirectories(parent)`。
3. `PackageParser.layerForEntry` 未接线 `ParseConfig.expandAllForPlainJar` 字段（dead config）→ 接入判定。
4. `MockAiAnalyzer.pick()` JSON 形态（如 `{"overallRisk":"MEDIUM"...}`）截取越界返回 `MEDIUMimpactScope:Y影响` → 修正 JSON 分支截取逻辑。
5. `PromptBuilders.sanitize()` 密钥正则 `(?:AK|SK|KEY|SECRET|TOKEN)[=_:\s-]*[A-Za-z0-9+/=]{8,}` 匹配不到带 `_` 的 `AK_SECRET_abc1234` → 放宽正则（金融合规脱敏漏网，P1）。
6. `HttpAiAnalyzer.extractContent()` 未还原 `\\n`/`\\t`/`\\"`/`\\uXXXX` 等 JSON 转义（输出 `行1n行2`）→ 补转义还原（AI 深读内容错乱，P1）。
