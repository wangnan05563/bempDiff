## P1 性能修复落地（缓存 / 流式 IO / 超时隔离）+ 真实 exe 重打包

用户"未受损，推进 P1"→确认 JDK8 基础设施未受影响，落实 P1-1/P1-2/P1-3。

### 实现
- P1-1（`Decompiler.java`）：进程内 LRU 反编译结果缓存。`decompileOne(byte[])` 先算 `sha256Hex(classBytes)` 作 key，命中即返回；否则走 CFR/javap 并回写。缓存 `Collections.synchronizedMap(new LinkedHashMap<>(...,true))` + `removeEldestEntry` 上限 256。消除 ai/report/export 对相同 class 的重复反编译。
- P1-2（`PackageParser.java`）：解析阶段全量 `byte[]` 缓冲 → 流式 SHA-256（`sha256Stream(ZipFile,ZipEntry)` 带 zip-bomb 守卫）；嵌套 lib jar 改 `copyEntryToTemp` 流式落盘单临时文件再哈希。降大包解析内存峰值 + 缓解 I/O 争用。
- P1-3（`Harness.java`）：全局有界 `WORK_POOL`（ThreadPoolExecutor + LinkedBlockingQueue(1024) + CallerRunsPolicy 背压）替每请求 newFixedThreadPool；有界 HTTP 接受池；每请求 `invokeAll(tasks, REQUEST_TIMEOUT_MS, ...)`（默认 10min）。同时 `Decompiler.cfr()/javap()` 加 `redirectErrorStream(true)` 消除子进程管道死锁。

### 验证
- `DecompileTest#testDecompile_cacheSameBytes_reusesResult`（缓存命中同引用）通过；ParseTest 8/8；全量单测 **45/45**。
- Harness 冒烟 `/health`→200、`/api/parse`→200（oldEntries 350/newEntries 409）。
- 真实 exe：`dist_exe/BempDiff/app/app.jar` 重打后，`VerifyP0` 跑 JDK21(=exe 内嵌 JVM)：`inProcessCfrAvailable=true`、`ENGINE_USED=cfr(in-process)`、`SRC_LEN=22585`（非降级）。✅

### 真实 exe 重打包（外科手术式，复用 P0-1 流程：不重跑 jpackage，仅换 app.jar）
- 编译：`javac --module-path <8 模块化 jar> --add-modules <...> -classpath cfr.jar -d app_prod` 全部 core+UI（34 class；Decompiler.class=10978=P1 版 vs 旧 9772）。
- 打 jar：`jar --create --main-class com.bempdiff.ui.App -f app.jar -C app_prod .`。⚠️ **必须用 GNU 长选项 `--create`，不能写 `jar cf --main-class ...`**——classic `cf` 模式会把 `--main-class` 当作 `-f` 的 jar 文件名而失败。
- 合并 cfr：`jar uf app.jar -C <cfr_extract> .`。⚠️ **关键坑**：cfr.jar 自带 `META-INF/MANIFEST.MF`（无 Main-Class）+ `META-INF/maven`。若 `jar uf` 把 cfr 的 META-INF 并进 app.jar，会**覆盖/抹掉 app.jar 的 Main-Class** → exe 无法启动 GUI。须先剔除 cfr 的 META-INF：用 Python `zipfile` 解压时**直接跳过 `META-INF/` 前缀条目**（不要靠 `shutil.rmtree` 删——会被 safe-delete 钩子 `BULK_CONFIRM` 拦截导致删除失败、META-INF 残留泄漏）。
- 落地：`python3 shutil.copy2(app.jar, dist_exe/BempDiff/app/app.jar)` 逐文件覆盖（绕 Defender 目录锁；仅 `BempDiff.exe` launcher 同名覆盖被锁，但字节一致不影响）。
- 校验：`jar tf` 确认 cfr=1362、Decompiler=1、PackageParser=1、无 `META-INF/maven` 泄漏；Python 读 `META-INF/MANIFEST.MF` 确认 `Main-Class: com.bempdiff.ui.App`。✅

## 脚本输出乱码修复（2026-08-10 16:3x）

用户报 `前端构建.bat` 输出中文警告乱码（`ע: ...ʹ����δ...`），且多打印一个 `0`。

### 根因
- `Invoke-NativeCmd` 旧实现：`& $Script 2>&1 | ForEach-Object { Write-Host $_ }` + 末尾 `return $LASTEXITCODE`。
  - `2>&1` 让 PowerShell 用默认 `$OutputEncoding`(ASCII/UTF8) 解码 javac 的 GBK 警告字节 → 乱码；再 Write-Host 写回 UTF-8 控制台 → 仍乱。
  - `return $LASTEXITCODE` 未接收即独立语句 → 把 `0` 打印到输出。
- javac 默认 JVM charset 在中文 Windows 是 GBK(Cp936)，警告走 stderr → 与 UTF-8 链路错位。

### 修复（build-ui.ps1 + package.ps1 同步）
1. `Invoke-NativeCmd` 改为直接执行、不捕获 stderr（`& $Script`），仅用 `$ErrorActionPreference='Continue'` 守卫防原生命令 stderr 触发终止错误；删除 `return $LASTEXITCODE`（消除多余 `0`）。javac 直接继承控制台写 UTF-8，配合 `.bat` 的 `chcp 65001` 正确显示。
2. javac 参数加 `-J-Dstdout.encoding=UTF-8 -J-Dstderr.encoding=UTF-8`（JDK18+ 属性），强制 javac 以 UTF-8 输出，任何中文编译错误在 65001 控制台也能正确显示。
3. javac 参数加 `-Xlint:-unchecked`，关掉 `Decompiler.java` 泛型原始类型那条不可操作的 unchecked 警告（避免在部分非 UTF-8 控制台变成空行/乱码）。真正的编译错误仍会出现。

### 验证
- 实跑 `build-ui.ps1`：无乱码、无多余 `0`、`BUILD_UI_EXIT=0`；沙箱非 65001 控制台下警告行呈空行（已靠 -Xlint:-unchecked 消除），用户本机 `chcp 65001` 下正常。

### 经验（编码）
- PowerShell 调原生命令输出含中文时，**不要** `2>&1 | ForEach-Object { Write-Host }`（会用 $OutputEncoding 误解码）。应让原生进程直接继承控制台 + 强制其 UTF-8 输出（`-J-Dstderr.encoding=UTF-8` 等），并确保调用方控制台为 65001（`chcp 65001`）。

## JavaFX UI 自适应修复（窗口/工具栏超出屏幕）

用户截图：启动后窗口宽度超出屏幕，工具栏按钮/输入框被截到右侧不可见。

### 根因
- `App.start()` 硬编码 `Scene(borderPane, 1280, 800)`，在较小屏幕/高 DPI 缩放下直接超出可视区。
- `buildToolbar()` 把路径输入框 + 5 个操作按钮 + 设置按钮全部塞进单行 `ToolBar`，水平空间不足时把场景强行撑宽。
- 主三栏 SplitPane 未设最小宽度，窗口缩小时区域被压扁。

### 修改
1. `bempdiff/javafx_ui/src/com/bempdiff/ui/App.java`：
   - 启动时按 `Screen.getPrimary().getVisualBounds()` 计算初始尺寸：`width = min(1280, max(960, 工作区宽-80))`，`height = min(800, max(600, 工作区高-80))`。
   - 设置 `stage.setMinWidth(900)` / `setMinHeight(540)`，防止用户缩到不可操作。
   - `buildToolbar()` 改为 `VBox` 两行：第一行 `ToolBar` 放两个路径输入框+浏览按钮；第二行 `ToolBar` 放操作按钮（左）+ `Region` spacer + 设置按钮（右）。小屏时自然换行，不会强制撑宽窗口。
   - `buildCenter()`：给 `treeView`/`oldSrc`/`newSrc`/`srcSplit`/`tabPane` 设 `setMinWidth`，保证基本可用宽度。
2. 运行时脚本同步：`bempdiff/javafx_ui/run_ui.bat` / `run_ui.sh` 更新为含 BootstrapFX/Ikonli 模块路径 + `cfr.jar` classpath，确保源码运行也能正确加载主题/图标/反编译。
