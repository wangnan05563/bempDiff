# 2026-08-31 工作日志

## 15:20 构建打包报 "No installer produced" —— PowerShell 5.1 编码坑 + 旧 exe 占用

### 现象
`tooling/scripts/构建打包.bat` 全流程跑通（javac/jar/jlink/vite/assemble 都 OK，electron-builder 也退出 0），
最后却报：
```
[STEP] Running electron-builder (NSIS) ...
  • output file is locked for writing (maybe by virus scanner) => waiting for unlock...
"[ERROR] No installer produced for version   - disk space issue or build failure. Check C:\ space."
```
注意 `for version   -` 中间**版本号是空的**；且 `release/BempDiff-0.1.2026083102-setup.exe`（122MB）其实是
11:47 那次构建的遗留物，本次（15:20）根本没写出新文件。

### 根因 1（主因）：PowerShell 5.1 按 ANSI/GBK 解码无 BOM 的 UTF-8 → ConvertFrom-Json 失败
bat 第 150 行原写法：
```bat
for /f "delims=" %%v in ('powershell ... "$p = Get-Content 'dev-shell\package.json' -Raw | ConvertFrom-Json; $p.version"') do set "_ver=%%v"
```
实测（PSVer=5.1.19041.6456）：
- `Get-Content` **不带 `-Encoding`** 时按系统 ANSI 代码页（GBK/CP936）解码文件；
- `dev-shell/package.json` 是**无 BOM 的 UTF-8** 且 `description` 含中文 → 解码后中文变乱码
  （`BempDiff 寮€鍙戞€?Electron 妗岄潰澹筹細`），引号被破坏；
- `ConvertFrom-Json` 在 offset 219 报错：`传入的对象无效，应为":"或"}"` → `$p.version` 为 **空**；
- 于是 `Join-Path '..\release' ('BempDiff-{0}-setup.exe' -f $env:_ver)` 拼成
  **`..\release\BempDiff--setup.exe`** → Test-Path=False → `.last_valid_exe` 写 0 字节 → 误报"未生成"。

> 这是跨项目通用坑，与用户级记忆里「无 BOM 的 UTF-8 中文 .ps1 被 PS5.1 按 GBK 解码」同源，
> 但这次落在**数据文件（JSON）**上：读取 JSON 必须显式 `-Encoding UTF8`，或改用 node / 正则。

对照实测：
- 文件首 3 字节 `7b 0d 0a`（`{`+CRLF）→ **无 BOM**，排除 BOM 假设；
- `node -p "require('./dev-shell/package.json').version"` → 正确返回 `0.1.2026083102`；
- PowerShell 正则 `[regex]::Match($c,'"version"\s*:\s*"([^"]+)"')` → 也能取到（version 是纯 ASCII）；
- 相对路径本身**没问题**：`Test-Path '..\release\BempDiff-0.1.2026083102-setup.exe'` = True
  （注意 `[System.IO.Path]::GetFullPath` 走的是 .NET CurrentDirectory，与 PS location 不同，别拿它判断）。

### 根因 2：旧 exe 被占用，electron-builder 跳过生成却仍 exit 0
`release/BempDiff-0.1.2026083102-setup.exe`（11:47 生成）被某进程占用（杀软扫描 / Explorer 预览 / 上次残留），
electron-builder 打印 `output file is locked for writing => waiting for unlock...` 后**没有产出新文件**，
但退出码仍是 0。而脚本的"存在即通过"检查会把那个**旧 exe** 当成本次产物 → 即便修好根因 1 也会误判。

### 修复（`tooling/scripts/构建打包.bat`）
1. **版本读取改用 node**（打包前读，实测输出 `0.1.2026083102\n`，**纯 LF 无 CR**，`set /p` 安全）：
   ```bat
   node -p "require('./dev-shell/package.json').version" > "..\release\.version" 2>nul
   set /p "_ver=" < "..\release\.version"
   ```
   （已实测 node v22.22.2 可读；用 node 而非加 `-Encoding UTF8`，是因为 node 的 require 天然处理编码，
   且不依赖 PS 版本行为。）
2. **打包前按版本号删除旧 exe + blockmap**（同时解决锁冲突与旧文件误判）：
   ```bat
   if exist "..\release\BempDiff-%_ver%-setup.exe" (
     del /q "..\release\BempDiff-%_ver%-setup.exe" >nul 2>&1
     if exist "..\release\BempDiff-%_ver%-setup.exe" ( echo [WARNING] 仍被占用 ... )
   )
   del /q "..\release\BempDiff-%_ver%-setup.exe.blockmap" >nul 2>&1
   ```
   删完再打包 → "存在且 >=50MB" 只可能是本次产出的，不再需要时间窗判定。
3. **校验改用绝对路径** `%CD%\..\release`（消除 CWD 歧义），且文件缺失时 `Write-Error` 打印
   `MISSING: <path> (ver=[...])` 到 stderr（原来静默失败，只留一个 0 字节的 `.last_valid_exe`，极难排查）。
4. `:dist_check_size` 段删掉重复的 `for /f` 读版本（已提前读），保留 `if not defined _ver` 兜底。

### 验证
- `node -p` 输出字节 = `0.1.2026083102\n`（无 CR）→ `set /p` 不会混入 `^M`；
- 相对/绝对路径 `Test-Path` 均为 True，确认 `..\release` 解析正常；
- 诊断临时文件（`release/_diag*.txt`、`_vtest.txt`）已用 ctypes `DeleteFileW` 清理干净。

### 环境备注
磁盘全线吃紧：C 8.2G / D 10G / E 2.6G / F 5.5G 可用。构建脚本已把 TMP/TEMP 重定向到
`release\.buildtmp`（D 盘）以避开 C 盘；若后续再出现磁盘类失败，先清 `release\.buildtmp` 与旧版本 exe。

## 15:5x 修复 AI 分析 HTTP 400「input tokens 195504 超过 max_prompt_tokens 131072」（提交 696fc07）
- **根因（护栏不对称）**：阶段B 早有 `STAGE_B_DIFF_CHAR_CAP=60000` 字符护栏，**阶段A 只有行数截断**（`stageAFileSampleLines=80`×`stageATopK=30`=2400 行、零字符上限）——压缩 JS/整文件重写等「单行超长」场景把 prompt 撑到 195504 tokens，被模型 131072 上限拒收。成本闸门只管费用确认、不管上下文窗口维度，用户确认后照发必然 400。
- **加重因子**：`ServerConfig.toAiConfig()` 只透传 `stageBTopK`，`stageATopK/stageAFileSampleLines` 未映射 → 阶段A 截断参数**无法从配置中心调节**（遗留问题，后续可暴露）。
- **修复**：① PromptBuilders 加 `STAGE_A_FILE_CHAR_CAP=8000`/文件 + `STAGE_A_TOTAL_CHAR_CAP=60000` 总量护栏（预算耗尽标注省略文件数）；② `HttpStatusException` 携带状态码，400/401/403/404/422 永久性 4xx 不再重试（原一律重试 2 次、超大请求体重传 3 次），仅网络/TLS/5xx/408/429 重试；③ token 超限错误翻译为可操作提示；④ `AiConfig.maxPromptTokens=120000` 发送前兜底拦截。
- **验证**：AiTest 新增 2 用例（单文件 40 万字符截断 / 30×8000 总量护栏+最坏情况估算 <131072），全量 **223/223 绿**（Zulu21 缺失回退 JDK25）。
- **⚠️ 工具链又双叒被掏空**：`toolchain/zulu21.../bin` 只剩 server 目录。`build_and_test.sh` 已加自动回退：Zulu21 缺失 → `dist_input/jre/bin/javac.exe`（实测是**完整 JDK25**，非瘦 JRE，含 javac）+ `--release 21` 保证字节码一致。产物已 `cp -r` 同步 `dist_input/classes`。
