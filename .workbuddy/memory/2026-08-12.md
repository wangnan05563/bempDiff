## WAR 全文件类型差异比对扩展（需求：覆盖 WAR 内所有文件类型）
此前 WAR 比对已支持 class 反编译、前端 JS/HTML/CSS 美化 diff、FolderDiff 文本 diff；但**包模式**有两处缺口：
- `.jsp`/`.tag`/`.tagx` 被分类为 `STATIC`（仅哈希，无内容 diff）—— 违背"JSP 内容级逐行比对"要求。
- `CONFIG`（XML/Properties/YAML/JSON）虽分类正确，但**从未做内容级 diff**，报告只列标记不展示实际改动。

### 落地改动（均已编译通过 + headless 验证 + 重新打包 EXE dist/BempDiff/BempDiff.exe）
- `FileClass`：新增 `JSP` 枚举；新增 `isTextDiffable()`（CONFIG/JSP/JS/HTML/CSS）与 `categoryLabel()`（报告按类型分组标签）。
- `PackageParser.classify`：JSP(.jsp/.jspx/.tag/.tagx) 先于 CONFIG 判定；CONFIG 扩 `.tld/.xhtml/.wsdl/.xsl/.xslt/.dtd/.vm/.ftl/.ini/.toml/.txt/.csv`；STATIC 增栅格扩展名、保留 `.svg` 作二进制哈希（按需求"图片"处理）。
- `FrontendTextDiff`：beautify 增 `JSP`（HTML 式拆行 + `<% %>` 断行）与 `CONFIG`（仅换行归一）分支；engine 标签区分 `jsp-normalize`/`text-normalize`。
- `DiffEngine`：新增 `collectTextDiffCandidates`（CONFIG+JSP+前端 全集，原有 `collectFrontendTextCandidates` 保留）。
- `MarkdownReport`：新增「### 按文件类型分布」表格（新增/删除/修改 按 categoryLabel 汇总，满足"清晰标注每种文件类型的变更情况"）；原「前端资源代码差异」通用为「文本类文件内容差异」（涵盖 CONFIG/JSP/JS/HTML/CSS）。
- `AssetExporter.sourceExtension`：文本类按原扩展名落盘（.xml/.properties/.jsp/.tag 等），不再统一 .java。
- `PromptBuilders`：阶段B 增 CONFIG/JSP 领域措辞；阶段A `fileClassOf`/`frontendLabel` 识别 CONFIG/JSP。
- `Main`：`buildFrontendMap`→`buildTextMap`（collectTextDiffCandidates），decompile/report/export/ai 全链路统一。
- `App.java`(GUI)：`isFrontend`→`isTextDiffable` 使 JSP/CONFIG 双击走文本 diff（不再"不支持"）；`buildTextMap` 同构替换。

## Req 6 — 差异依赖 JAR 自动识别/提取/反编译/源码级比对（本窗口落地 + 打包复验）
**目标**：自动识别 WAR 中存在差异的第三方依赖 JAR（L2，`/lib/*.jar` 且 status∈{ADDED,MODIFIED,DELETED}），对其内部 class 反编译并逐文件源码级 diff，输出清晰对比报告。内部业务 lib（展开为 L1 的 class）不在此重复（已由 `collectL1ClassCandidates` 覆盖）。

### 改动文件
- **新增 `java_core/.../diff/LibJarDiff.java`**（核心引擎）：
  - 三个结果模型：`LibClassUnit(innerClass, status, unit)`（`unit=null` 表示未预反编译，待 GUI 懒加载）、`DiffJarInfo(jarKey, jarStatus, added/removed/modified/unchanged, classes)`、`Result(jars, 总数+各类计数)` + `isEmpty()`。
  - `identifyDiffJars(DiffResult)`：筛 `k.endsWith(".jar") && k.contains("/lib/")` 且状态为 MODIFIED/ADDED/DELETED。
  - `analyze(oldSnap,newSnap,r,dec,topK)→Result`；`analyzeJar(...)`：读 old/new jar 字节→`classShaMap`(TreeMap 稳定排序)→逐 class 状态(ADDED/REMOVED/MODIFIED/UNCHANGED)→Top-K 反编译（`dec.decompileBytes(ob,nb,inner)`）→组装全量 `LibClassUnit`。
  - `readClassBytes(snap,jarKey,inner)`：懒加载单 class 字节，供 GUI 点击未预反编译项。
  - 内部工具：`jarStatusOf` / `readJarBytes`（经 `new PackageParser().readEntryBytes`）/ `classShaMap` / `readClassBytesFrom` / `writeTempJar` / `sha256`（含 zip-bomb 防御 HARD_CAP=64MB）。
- **`decompile/Decompiler.java`**：新增 `decompileBytes(byte[] old, byte[] new, String key)`——直接对原始 class 字节反编译（进程内 CFR），返回 `DecompiledUnit`（含 unifiedDiff + 降级标记 + 引擎标签 `cfr(in-process)`）。
- **`report/MarkdownReport.java`**：`render`/`writeToFile` 6 参→7 参（传 `libJar`，null 委托旧签名）；原 9 参→10 参（含 `libJar`）；新增 `renderLibJarDiff(sb, libJar)` 输出「## 五、差异依赖 JAR 内部源码对比（Top-<k> 内部 class 反编译源码级 diff）」：总览（差异 JAR 数 + 内部 class 合计）+ 每 jar 内部 class(+/-/~/=) + 已反编译单元 `#### <inner> [状态]` 代码块 + 未展开提示。章节重排：breaking→六、footer 按 `aiEnabled` 动态 `七/八`、AI→七，保证升序无缺口。
- **`Main.java`**：`report` 加 `LibJarDiff.analyze(...)` 并传 libJar；新增 `diffJars(old,new,expandAll,topK,cfrJar,out)` 子命令（打印按 jar 状态计数 jarAdded/jarModified/jarDeleted + 聚焦报告）；`switch` 加 `case "diff-jars"`，`usage` 加说明。
- **`javafx_ui/.../App.java`**：`makeReportTask` 加 `LibJarDiff.analyze` 传 libJar；`onTreeSelect` 命中 `isDiffLibJar`（JAR && L2 && `/lib/` && `.jar`）→ `showLibJarDiffTab`；新增 `showLibJarDiffTab` / `showLibJarContent`(ListView 状态着色 CellFactory，点击已反编译项 `showDiffViewTab` 否则 `decompileLibClassAndShow` 懒加载) / `decompileLibClassAndShow`(Task 调 `readClassBytes`+`decompileBytes`)。
- **`verify_exe/make_test_wars.py`**：新增 `compile_lib_class`(包 `org.difflib`，避开默认 `com/` 内部前缀) / `make_diff_lib_jar`；`files_v1/v2` 注入 `WEB-INF/lib/diff-lib.jar`（v1 仅 Helper，v2 含 Helper+Extra）。
