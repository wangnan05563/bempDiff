## 本会话代码改动评审（stripTrailing 两处 + 5 处测试断言）
- 总体结论：改动量小且无高危缺陷；stripTrailing 仅裁展示层尾部空白、不改 diff 语义，folderdiff 验证 exit 0 干净，无回归。
- 一致性隐患（低）：`Main.printFolderTree` 对 `lineDiff` 仅判 `!= null`，而 `FolderReport.render` 判 `!= null && !isEmpty()`。若 `lineDiff` 非空串，`Main` 会多打一行缩进空白（`split("\n")` 对 `""` 得 `[""]`）。当前 `LineDiff.unified` 对内容不同文件几乎不可能返 `""`，实际不可达，但两处守卫应统一（建议 `Main` 也加 `!isEmpty()` 或抽公共 helper）。
- 既有重复（非本次引入，架构异味）：`Main.printFolderTree` 与 `FolderReport.appendTree` 各自复制 marker 映射 / subtreeDiff 计算 / name 提取 / attrSummary 逻辑，改动任一处需同步两处，存在漂移风险；建议抽 `FolderEntryFormatter` 公共 helper。
- CRLF 行尾（既有，非本次引入的观察）：两处均 `split("\n")`，若 diff 含 `\r\n`，中间行会带尾随 `\r` 进入控制台与 ```diff 块；stripTrailing 只清末尾 `\r\n`，不改此现状。
- 测试改动评估：5 处断言均对齐有意设计（JSP/CONFIG 分类、Top-K 精准计数、章节四标题、移除 6 参数 render 对 AI 章节的错断言），未掩盖真 bug；唯一覆盖率小缺口——`testRender_sectionsComplete` 未断言 6 参数 render 不含 AI 章节，可补 `assertNotContains("## 七、AI 智能分析")` 锁契约。
